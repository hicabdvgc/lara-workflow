# Stage 2. Design document specification

Use this specification for Stage 2 of [Behavioral Experiment Workflow.md](<../Behavioral Experiment Workflow.md>). Develop the study concept in CONCEPT.md and the author's experimental decisions into DESIGN.md, using the outline below. DESIGN.md is the authoritative statement of the experiment's intended design.

Preserve the author's decisions and describe the applicable requirements in complete, precise language. Examples in the outline illustrate possible content; include screening, grouping, randomization, counterbalancing, or other procedures when the study requires them. Resolve ambiguities that affect experimental behavior with the author before finalizing the affected content.

Repeat the component entries as needed for the actual experiment. Replace example component names with the study's component names and remove the ellipsis entries. Save the completed DESIGN.md at the experiment root. The remaining development stages are described in the workflow document.

# DESIGN.md outline

# I. Overview
- Here, the author explains what the test will be about, what it aims to assess, and general information about its theoretical background, relevant concepts, etc.
# II. Participants
- Here, the author explains the following: 
	- How the participants are going to perform the test (locally, online, etc.)
	- How the participants are going to be screened, and with which particular component in the procedure will the screening variable be collected (e.g., a questionnaire, or a particular answer within a questionnaire) 
	- If there are any grouping of the participants, and with which particular component in the procedure will the grouping variable be collected (e.g., a task or questionnaire, or a particular performance result within a task) 
	- If, once the participants are grouped, are there any orders, sequencing or particular treatments for different groups of the participants (e.g., counter-balancing any tests, having a latin-square design, etc.)
# III. Procedure
- Here, the author explains the sequencing of the components of the experiment. For instance, where to begin, what's tested first, what's tested next, where's the end of the experiment, etc. 
- This is also where the author explains any non-task-specific randomizations and/or other manipulations of the experiment; that is, anything that applies to the entire experiment (but not specific tasks) goes here.
# IV. Task-by-task Breakdown
- Here, the author explains each component in detail, including its required content and materials, presentation, participant actions, response meanings, timing, and completion conditions. Include questionnaires, tasks, checkpoints, and other components according to the actual experiment.

# VI. Results Handling
- Later statistical preprocessing and analysis are outside this experiment-development workflow. This section describes result handling during experiment execution and delivery.
- Here, the authors describe how results from each component should be stored, categorized, and delivered. Depending on the study's requirements, this may include completion notifications, online storage, local result destinations, individual session records, combined files, or separate files organized by specified conditions.
# VII. Additional Information
- Here, the author makes clear additional customizations they want to implement for the study.
