# Write Design Document

Apply the Designer perspective to Stage 2 of the [experiment workflow](<../../../Behavioral Experiment Workflow.md>). Produce an accurate, structured account of the researcher's experimental decisions.

## Read the specification and inputs

Read [Design Doc Schematics.md](<../../../workflow-templates/Design Doc Schematics.md>) before writing. Resolve this reference relative to this skill's directory and follow its seven-section outline.

Read the established design, relevant conversation decisions, source notes, and available concept or materials. For revisions, read the existing `DESIGN.md` and identify the requested scope. A completed `CONCEPT.md` is optional when the user has supplied equivalent design requirements.

Identify contradictions or missing decisions that prevent faithful documentation. Ask the researcher to resolve those issues before finalizing dependent content. Use `design-experiment` when the requested work includes developing new operational decisions; do not select missing experimental values merely to complete the outline.

## Synthesize the document

- Explain the study's purpose and relevant background using the established design and supported references.
- Describe participation and the applicable screening, allocation, and group differences. Identify where decision-making information is collected and how it affects the procedure.
- Connect the overall sequence, transitions, repetitions, and design-defined branches to the component descriptions. Keep experiment-wide rules distinguishable from component-specific rules.
- Repeat component entries according to the actual study. Describe content, material requirements, presentation, participant actions, response meanings, timing, and completion at the detail established by the design.
- State required observations, measurement meanings, units, calculations, and any established inclusion, exclusion, or performance criteria. Keep the component names consistent between the breakdown and the outcomes.
- Describe recording, organization, storage, and delivery requirements in Results Handling. Later statistical preprocessing and analysis remain outside that section's workflow scope.
- Place additional study-specific requirements in the relevant sections or Additional Information as appropriate.

Preserve fixed wording, quantities, instrument versions, and meaningful material relationships. Include the researcher's instructions and their intended placement when they form part of the experiment. Reference separate briefing materials where they are relevant to understanding the procedure.

Use actual component names and content. Remove example entries and ellipses. Examples of questionnaires, grouping, and counterbalancing in the specification are conditional possibilities; they do not prescribe this study's methodology.

## Save and verify

Save the completed `DESIGN.md` at the established experiment root or the user's explicit destination. Resolve an ambiguous destination before writing; the workflow toolkit's root is not automatically the study project. Preserve unaffected content when updating an existing document.

Check that the seven sections are present, repeated entries reflect the actual components, procedure and component descriptions agree, and outcomes correspond to the defined observations. Verify that material references resolve where files are supplied and that no unsupported experimental choice has been introduced. Update the existing `LIB.md` when the document's location is newly added or changed.

Return the document link and a brief account of substantive changes. Keep clarification requests and preparation commentary outside the completed document. A request limited to a conversational draft can be delivered in that form. Creating the schema, formatting assets, and implementing the experiment are separate outputs.
